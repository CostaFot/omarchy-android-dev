## What exists (0.5.0: the Python core, the service, the bar widget, the hub and its first nine pages)

## The helper contract

```
/usr/bin/python3 bin/omarchy-android-dev [--settings '<json>'] [--serial S] <command> [args]
```

`--settings` carries the plugin's shell.json scalars (`adbPath screenshotDir recordingDir apkDir scrcpyArgs notify deviceNotifications confirmUninstall showSystemApps`); unknown keys are ignored, defaults are in `cli.SETTING_DEFAULTS` and must match `manifest.json` (`test_manifest_defaults_match_the_helper` pins both the values and the schema order); each value takes the type of its default (`coerce_setting`), so a boolean given as the word `"false"` is false. `--serial` wins over the remembered device.

Envelope on every document: `schema_version:1, command, ok, error, generated_at, adb:{path, source}`, then the payload; device commands add `selected`. `error` is `{code, message, stderr?}` with codes `no_adb no_device many_devices unauthorized offline adb_failed bad_args timeout too_much_output state_corrupt no_tool internal` (`no_tool`: scrcpy, the emulator, the terminal launcher or wl-paste is missing or exited at once). **A document can carry `ok:true` and an error at the same time** (`state_corrupt` rides with a good answer); consumers treat "has data" and "has error" independently. `notice` is the one-line human result the panel shows and a notification carries.

| Command | Payload |
|---|---|
| `status` | `version python state_dir state_dir_text screenshot_dir screenshot_dir_text recording_dir recording_dir_text apk_dir apk_dir_text tools:{scrcpy emulator terminal wl_copy wl_paste}:{found path} adb_version devices selected last_package recent_deeplinks`; with no adb: `error.code no_adb`, the rest still filled; `last_package` is the one remembered for the selected serial (`null` with none) |
| `devices` | `devices[] {serial state model product device transport_id kind avd label detail selected}`, `selected`; `kind` is `emulator` (`emulator-*`, `localhost:*`), `wifi` (a `:` in the serial) or `usb`; `label` is the AVD name from `emu avd name` for a running emulator, else the model with `_` → space, then ` (SERIAL)`; `detail` is `Emulator · ready`, `USB · needs authorising: accept the prompt on the device`, `Wi-Fi · offline` (`fmt.device_detail`), the hub's second line |
| `select SERIAL` | writes `state.selected`; `devices selected notice` |
| `track` | streaming: `{"event":"devices", devices, selected, added[], removed[], unauthorized[], initial}` per frame of `adb track-devices` (details from one `devices -l` per frame; the state file is re-read per frame so a `select` from another run is seen); `{"event":"error", error}` once when adb is missing or goes away, then exit 0; SIGTERM/SIGINT end it and the adb child with it; the helper and the adb child both carry `PR_SET_PDEATHSIG` SIGTERM, so a SIGKILLed helper or a crashed shell leaves nothing behind |
| `packages` | `packages[] {name running foreground debuggable section detail}` sorted Foreground → Running → Debuggable → name; `detail` is the Windows subtitle (`foreground · debuggable`, `running`, `debuggable` or empty; `fmt.package_tags`); `foreground count system_apps last_package`; `debuggable` is `null` until that package has been opened once |
| `package PKG` | `name version_name version_code debuggable launcher_activity runtime_permissions[{name granted}] running foreground`; remembers `last_package` per serial and the debuggable flag for the next list |
| `app ACTION PKG` | `notice action package`, `activity` for the launches; ACTION ∈ `launch restart force-stop kill clear clear-restart uninstall` |
| `perms grant\|revoke PKG` | `notice granted\|revoked total failed[]`; every `name: granted=…` line under the first `runtime permissions:` block, whatever its prefix |
| `deeplink URL [PKG]` | `notice url package recent_deeplinks[]` (10 kept); the URL must have a scheme and no whitespace or control characters |
| `screenshot` | `notice path path_text size size_text copied notified warning` |
| `record` | streaming, no arguments: `{"event":"recording", device_path, directory, directory_text, started_at}` once `adb shell screenrecord /sdcard/omarchy-android-dev-<stamp>.mp4` has survived its first half second (a notification goes out with it), then one final envelope when the recording ends: `{"event":"recorded", notice path path_text size size_text seconds seconds_text device_path removed notified warning}` or `{"event":"error", error}`; every line is a full envelope with `selected`. It ends on SIGINT or SIGTERM (Ctrl-C in a terminal, `recorder.signal(2)` from the service: the adb client gets SIGTERM, adbd hangs up the shell, screenrecord finishes the file on SIGHUP), or on screenrecord's own 180 s limit. Then `stat -c %s` until the device file stops growing (5 s ceiling), `pull` to `<recording dir>/android-<stamp>.mp4` (120 s), `rm -f` (a failure is `warning`, the file named), notification. A screenrecord that fails at once is one `error` line and nothing else. Exit 0 always; the whole-run alarm is disarmed like `track`'s |
| `toggles` | `toggles:{animations touches pointer layout airplane wifi data bluetooth}:{on text label}`, `api`; `on` is `null` and `text` `unknown` when the device answers nothing readable |
| `toggle NAME [on\|off]` | `notice toggle on toggles api` (the fresh states after the flip); the IPC verb for it is `flip NAME` |
| `apk list [DIR]` | `dir dir_text exists apks[{path path_text name size size_text}] count truncated`; DIR defaults to the `apkDir` setting; top-level `*.apk` (any case) sorted by name, MAX_APKS 200; a missing folder is `exists:false` and `ok:true`; no device needed |
| `apk install PATH...` | `results[{path name ok message code?}] installed total notice`; `adb install -r -t PATH` per file in order (120 s each); a failed file's `message` is adb's `Failure [...]`; one file: `notice` `Installed: NAME`, or `ok:false` with `Install failed: …`; several: `Installed n/m APKs`, `ok:false` when any failed, the results ride along (`PartialError`) |
| `text send TEXT` | `notice text source length`; `shell input text <encoded>` where spaces are `%s` and the whole is `shlex.quote`d for the device shell; refused (`bad_args`) when empty, over 500 characters, with line breaks or anything outside printable ASCII |
| `text clipboard` | the same after `wl-paste --no-newline -t text` (5 s, 64 KiB); `no_tool` without wl-paste, `bad_args` `The clipboard is empty` / `does not hold text` (an image) / too big |
| `tools` | `tools:{scrcpy emulator terminal wl_copy wl_paste} avds[{name running serial detail}] avd_count scrcpy_args`; AVDs from `emulator -list-avds` (15 s), `running`/`serial` from the ready emulators' `avd` names; `detail` is `Running · emulator-5554` or `Stopped` (`fmt.avd_detail`); works without adb (`no_adb` rides along, nothing Running) |
| `tool scrcpy` | `notice argv`; launches `scrcpy -s SERIAL --window-title "Android Dev" <scrcpyArgs split on whitespace>` detached, with `ADB` in its environment naming the adb the helper resolved |
| `tool avd NAME` | `notice avd`; launches `emulator -avd NAME` detached; `bad_args` when NAME is not in the list or already running (`NAME is already running (SERIAL)`); works without adb |
| `tool avd-stop SERIAL` | `notice serial`; `adb -s SERIAL emu kill`; `no_device` when not attached, `bad_args` when not an emulator |
| `tool logcat [PKG]` | `notice package argv`; `xdg-terminal-exec --title=… <adb> -s SERIAL logcat [--pid=<pidof PKG>]` detached; `adb_failed` `PKG is not running; launch it first` when pidof finds nothing; remembers PKG as `last_package` |
| `help` | `commands[{usage text}] text` |

Serial rule (`devices.resolve_serial`): `--serial` wins; else `state.selected` if that device is still attached; else the only attached device; else `many_devices`/`no_device`. Then `require_ready`: a device in state `unauthorized` or `offline` is its own error code with the hint the user needs, before any device command runs.

adb resolution (`adb.resolve`): `OMARCHY_ANDROID_DEV_PATH` overrides everything (tests; a non-executable value means "no adb"); else the `adbPath` setting (a file, or a directory containing `adb`); else `$ANDROID_HOME`/`$ANDROID_SDK_ROOT` `platform-tools/adb`; else `~/Android/Sdk/platform-tools/adb`; else PATH. `status` reports which as `adb.source` (`override setting env home path`).

Environment: `OMARCHY_ANDROID_DEV_STATE_DIR` (tests), `OMARCHY_ANDROID_DEV_DEBUG=1` (argv, exit codes and byte counts on stderr; nothing on stdout), `OMARCHY_ANDROID_DEV_TOTAL_BUDGET` (whole-run alarm, 60 s, 0 disables; `track` and `record` disarm it), `OMARCHY_ANDROID_DEV_NOTIFY` / `OMARCHY_ANDROID_DEV_WL_COPY` / `OMARCHY_ANDROID_DEV_WL_PASTE` / `OMARCHY_ANDROID_DEV_SCRCPY` / `OMARCHY_ANDROID_DEV_EMULATOR` / `OMARCHY_ANDROID_DEV_TERMINAL` (fake scripts in tests; a non-executable value means "not installed"), `OMARCHY_ANDROID_DEV_LAUNCHER` (replaces `uwsm-app` in front of a detached launch; empty runs the tool directly, the tests do that), `OMARCHY_SCREENSHOT_DIR` and `OMARCHY_SCREENRECORD_DIR` (Omarchy's own; else `XDG_PICTURES_DIR` / `XDG_VIDEOS_DIR` from `~/.config/user-dirs.dirs`, else `~/Pictures` / `~/Videos`; the `screenshotDir` / `recordingDir` settings win over all of it), `ANDROID_ADB_SERVER_PORT` / `ANDROID_ADB_SERVER_ADDRESS` (adb's own; the tests set the port to a closed one).

## The QML side

- **Service.qml** is an `Item` (a `QtObject` has no default property for the `Process`), created by the shell with `shell manifest omarchyPath` injected, only while the plugin is enabled (`shell.qml _syncServices`), and destroyed on disable. It owns the one `Store`, the tracker, the notifications and the one `IpcHandler { target: "costafot.android-dev" }` (two handlers on one target is a shell warning and the second is ignored; `Panel.qml` sets `manageIpc: false` for that reason). Bar widgets call `registerHost(widget)`/`unregisterHost` (one per monitor); `hostSettings` is the first host's `settings` (the shell injects settings only into bar widgets) and reaches the Store and the tracker as `--settings`; with no host the helper runs on its defaults. Panel verbs go through `shell.summon/hide` so the widget on the focused monitor answers; `page` uses the open host, else the first.
- **The tracker** is `Process { stdout: SplitParser }` running `sh -c 'exec "$0" "$@"' /usr/bin/python3 <pluginDir>/bin/omarchy-android-dev --settings … track`. Every line is parsed on its own (`applyTrackerLine`: a `devices` event replaces `store.devices`/`selected` and resets the backoff, an `error` event sets `trackerError`; `no_adb` also blanks `store.adbInfo` so the hub shows the note). `onRunningChanged` to false restarts it after `trackerBackoffMs` (5 s doubling to 60 s), or at once when `trackerRestartPending` (a `settingsJson` change, through a `Connections` on the store). `stopTracker()` sends SIGTERM (`tracker.signal(15)`); the helper forwards it to adb. **The shell ends the helper with SIGKILL on destroy**, which no handler can forward: seen 2026-09-05 as an orphaned `adb track-devices` after `omarchy plugin disable`; fixed by `PR_SET_PDEATHSIG` on the adb child (`adb.popen`, `preexec_fn=die_with_parent`) and on the helper itself (`track`), tested by `test_track_helper_killed_outright_takes_adb_with_it`. The producer-side cap for the stream is the helper's own (32 devices, 256-character fields); a line over 64K characters is dropped as `too_much_output`.
- **The recorder** is a second `Process { stdout: SplitParser }` in the service running `… --settings … record`, started by `startRecording()` (`recorder.command` assigned fresh each time, one recording per shell), stopped by `stopRecording()` = `recorder.signal(2)` (SIGINT, what Ctrl-C does in a terminal; the helper handles SIGTERM the same way). `applyRecorderLine`: a `recording` event sets `recording` and `recordingStartedAt` (a 1 s `Timer` bumps `recordingSeconds` while it runs; `elapsedText(s)` formats `m:ss` for the panel and the tooltip); the final line goes through `store.handle(text)` like any run, so its `notice` is the panel's and its `error` is `lastError`, and a failure gets a notification here (the helper sends its own for the saved file). `recorderExitFallback` (300 ms after the process ends) catches a run that printed no final line (could not start, killed): an urgent "ended without an answer" notice. `recordingStopping` is true between the signal and the answer; the Capture page shows "Saving the recording…" then. `statusJson` carries `recording:{active stopping seconds device_path}`. On destroy the recorder gets SIGINT but the shell SIGKILLs it right after; PDEATHSIG ends the adb client, screenrecord finishes the file, and the mp4 stays on the device at `/sdcard/omarchy-android-dev-<stamp>.mp4` (the documented limitation; `IDEAS.md` has the pull-the-leftovers idea).
- **Device notifications** (`notifyDevices`): skipped on the `initial` frame and when `notify` or `deviceNotifications` is off; a serial in state `device` that was not ready on the previous frame (`knownReady`) → "Android device connected", `removed` → "Android device disconnected", `unauthorized` → "Android device needs authorising" once per serial while it stays so. "Connected" means *became ready*, not *appeared*: an emulator appears as `offline` with no model (the first toast said `emulator-5554`, seen 2026-09-05) and is ready a minute later with its AVD name; a phone appears ready or `unauthorized`. Labels for a removed device come from `knownLabels`, which keeps the label from the last frame where the device was `device`: an emulator on its way out passes through `offline`, where `emu avd name` no longer answers and the label falls back to the model. Sent as `Quickshell.execDetached([omarchyPath + "/bin/omarchy-notification-send", "--app-name", "Android Dev", "-g", glyph, headline, body])`, argv only.
- **Store.qml** is Markets' Store (`run(args, onDone)`, one `Process` through `/bin/sh -c 'exec "$0" "$@"' /usr/bin/python3`, last-command-wins `pendingRun`, `collectorDone`+`processDone` with the 300 ms `exitFallback`, 1 MiB `StdioCollector` tripwire, `helperBudgetSeconds` 60 as `OMARCHY_ANDROID_DEV_TOTAL_BUDGET` through `proc.environment` assigned in `run()`, `killTimer` SIGTERM 10 s after the budget then `killFallback` SIGKILL 5 s later) plus **`runGen`**: every run increments it and each timer carries the generation it was armed for, so a stale timer from a killed run never fires into the next one; a `timedOut` run is reported as `timeout` whatever it printed. Merge rule in `handle()`: `adb` → `adbInfo` always; `command:"status"` → `status`; a `devices` array → `devices` + `selected`; `packages` → `packages` + `packagesInfo`; `toggles` → `toggles`; a `command:"apk"` document with `apks` → `apkList`; a `command:"tools"` document with `avds` → `toolsInfo`; `recent_deeplinks` → `recentDeeplinks`; `last_package` (present, even `null`) → `lastPackage`; a good `command:"package"` → `packageDetails[name]`; a good `app uninstall` drops that package from `packages`; `error` → `lastError`/`lastErrorCode` without blanking anything; `notice` → `showNotice` (3 s), and an `ok:false` error message becomes an urgent notice. `runningCommand` is the first argv word of the run in flight (`""` between runs) so a page can tell its own "Listing packages…" from someone else's run. `applyTrackerEvent(ev)` is the tracker's way in (no queue). `onSelectedChanged` blanks `toggles`: they were read from one device. No polling timer anywhere: the tracker pushes devices, the panel refreshes `status` on open and `r`, `packages` on entering the Apps page, `package PKG` on entering an actions page, `toggles` on entering the Toggles page and after every flip (the flip's document carries all eight), `apk list DIR` on entering the APKs page and 300 ms after the folder box changes, `tools` on entering the Tools page, after a Start or Stop, and whenever the tracker changes the device list while that page is open (an emulator leaves the list a few seconds after `emu kill`, once its snapshot is saved; a started one joins when it boots, 8 s with quickboot here), so a freshly installed scrcpy shows up without a restart and the Running/Stopped rows follow the devices.
- **`Service.act(args, onDone, silent)`** is the one path for everything that changes the device, from the panel and from the IPC verbs alike: `store.run(args)`, then a notification with the helper's `notice` as the headline and the selected device's label as the body (`store.lastError` when the run failed), skipped for `screenshot` (the helper sends its own), when `notify` is off, or when `silent` is true (the APK page's Install all passes it and sends one `Installed n/m APKs` summary through `service.notify` instead); the panel shows the same notice as its row. IPC action verbs (`launch forcestop clear deeplink flip text clipboard scrcpy avd logcat`) check the argument shape (`validPackage`: `[A-Za-z0-9_.]`, 256 chars; a URL: no whitespace or control characters, 2 KiB; a toggle name from `toggleNames`; `validText`: printable ASCII, 500 chars; `validAvd`: `[A-Za-z0-9._-]`, 64 chars; `logcat` with no argument follows the whole log) and answer `requested`; the helper validates again and a `bad_args` comes back as an urgent notice and a notification. `record start|stop|toggle` answers `requested`, `stopping`, `already recording` or `not recording`; `page` accepts `hub devices packages deeplink toggles capture apks text tools`.
- **BarWidget.qml**: `svc = bar.shell.serviceFor("costafot.android-dev")`, `visible: svc !== null`; registers with the service (`register()` on `Component.onCompleted` and `onSvcChanged`, unregisters on destruction); the panel contract for the shell's summon/hide routing (`opened open close togglePanel popoutSwitchClosing closeForPopoutSwitch`) proxies to the loaded `Panel.qml`, held as an untyped `var`; `injectPanel()` hands it `bar settings anchorItem hostWidget service`. The `WidgetButton` shows the droid glyph (`"\uf17b"`, always as a JS escape: the Write tool stripped every literal PUA glyph from `Panel.qml` on 2026-09-05 and left `""` behind silently) plus ` ●` (U+25CF, a plain character) while `svc.recording` and the count when > 1, `dimmed` with no device, `active` (the urgent colour) when the selected device is not in state `device` or a recording runs; the tooltip is the label with the state, the count and `recording m:ss`. Left click toggles the panel, middle click `store.refreshStatus()`.

the cursor jumps to the typed row on every change, so Enter takes it); **tools** (`Reading the tools…` / `Press r to read the tools` without a document; with a ready device: `Mirror with scrcpy` when `tools.scrcpy.found` (the detail names the command and `scrcpy_args`) else a `scrcpy not installed` note, and `Logcat · <last package>` or `Logcat` when `tools.terminal.found` else a note; otherwise the gate's note; then the `Emulators` header and one row per AVD with a stop or play glyph, the helper's `detail` plus `· Enter stops it` / `· Enter starts it`; Start runs `tool avd NAME` and re-reads `tools` after; The confirm dialog is one `ConfirmDialog` fed by `confirmRow`: `confirmMessage`/`confirmText` derive from the row's `action` (`uninstall` or `avdstop`), `acceptConfirm` dispatches on it. The hub shows an urgent `Recording · m:ss` note under the device row while a recording runs. Everything that changes the device goes through `service.act`. Keys: `j/k`/arrows move, Enter activates, `r` refreshes the page's own data, Escape pops (closes on the hub, cancels the dialog first), Backspace pops through a `Keys.onPressed` on the catcher's parent (in the field it edits, and pops only when empty), Tab switches bar panels (from the field it moves focus to the list), `/` focuses the field. The catcher is `blocked` while the field has focus or the dialog is open; the dialog's keys arrive through the same parent handler (`confirmDialog.handleKey`). Width `fittedContentWidth(Style.space(380))`, height capped at `Style.space(760)` plus the field. Every `Text` is `Text.PlainText`; the strings built around device data are the uninstall question (`Uninstall PKG? This will remove…`), the stop question (`Stop NAME? …`) and the `Logcat · PKG` row label; everything else the panel shows is a literal or a field the helper formatted.

## Hard-won constraints — do not re-litigate without re-testing

- **Never crash.** `cli.main` catches `BaseException`; a traceback on stdout would be parsed as garbage by QML and blank the bar. Errors ride inside the JSON. Verified: `bin/omarchy-android-dev bogus; echo $?` → 0.
- **Every adb call goes through `Adb.run`**: absolute binary, argv list, `-s SERIAL` on every device command, `timeout=` (10 s default, 60 s for uninstall, 30 s for screencap, none for `track`), `cap=` (256 KiB default, 1 MiB for `pm list`/`dumpsys`, 20 MiB for screencap). The reader threads stop at the cap and kill the child; `too_much_output` is an error, never a parse. Package names, URLs and paths are single argv entries; the Windows `\"…\"` quoting must not be copied. The one shell script in the tree (`toggles.READ_SCRIPT`) is a fixed string with no device data in it.
- **The failure rule is wider than Windows'**: exit code ≠ 0, or `error:` on stderr, or a stdout line starting `Failure`, `Error:` or `Failed`. `pm clear` on an unknown package prints `Failed` with exit 0; `adb uninstall` prints `Failure [DELETE_FAILED_INTERNAL_ERROR]` with exit 1; both are caught (`shell pm uninstall` exits 0 on failure, which is why `uninstall` uses the host verb).
- **`ensure_server()` runs once per helper run**, under `flock` on `<state dir>/adb-server.lock` (non-blocking loop, 10 s ceiling). Under the lock: a stamp written by another holder within 10 s means skip; a connect to adb's server port that succeeds means skip; otherwise `adb start-server`, then write the stamp. Dori PR #4 is the crash this prevents (two clients at login, one aborts on the busy socket). `test_two_helpers_at_once_start_the_server_once` runs two helpers against a fake that sleeps in `start-server`.
- **Cold-start banner.** The first adb call after boot prints `* daemon not running; starting now at tcp:5037` / `* daemon started successfully` on stdout ahead of its result; `fmt.lines()` drops every line starting with `*`. Fixture `devices_l_coldstart.txt`.
- **`screencap -p` on the foldable emulator prints `[Warning] Multiple displays were found…` ahead of the PNG** (seen 2026-09-05, API 37). `capture.split_png` looks for the signature within the first 4 KiB, keeps the image and returns the text as `warning`. Anything without a signature is `adb_failed` and no file is written.
- **The foreground package** comes from `dumpsys window` `mCurrentFocus=Window{… u0 PKG/ACTIVITY}` (still there on API 37) with `dumpsys activity activities` `topResumedActivity=` as the fallback. `ps -A` rows are matched on the `u0_a*` user and the last column with any `:subprocess` suffix removed, so a package with only a service process counts as Running (Windows compared the raw name and missed those).
- **`dumpsys package PKG` prints the package twice** for an updated system app (the installed copy under `Packages:`, then the stub under `Hidden system packages:`); `parse_package_dump` reads the first section only and stops at the second header. Runtime permissions are the first `runtime permissions:` block (user 0), ended by a dedent.
- **Emulator labels** cost one `adb -s SERIAL emu avd name` per running emulator per `devices` call (5 s timeout, `OK` line skipped). A phone's label is its model with `_` → space. `devices -l` states include `no permissions (…)` with spaces; the parser handles it.
- **Toggles are read in one `adb shell`** (`toggles.READ_SCRIPT`: `api=`, `layout=`, then `namespace:key=value` lines). Animations are on unless `window_animation_scale` is `0`; a `null` setting is "never set" (off for touches/pointer/layout/airplane, unknown for wifi/data/bluetooth). Airplane mode uses `cmd connectivity airplane-mode enable|disable` on API ≥ 30 and `settings put` + the broadcast before that. Layout bounds needs `service call activity 1599295570` after `setprop debug.layout`. Every flip re-reads and returns all eight.
- **State files** (`state.py`): the dir is verified on every run (not a symlink, a directory, owned by us, no group/other bits; a failing dir means no state is read or written and `state_corrupt` rides in the envelope); reads open `O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC`, `fstat` a regular file under 64 KiB and read through the descriptor; a symlink (`ELOOP`), an oversized or an unparsable file is renamed to `<name>.bak.<ts>` (rename never follows the link) and reported once; writes are `mkstemp` in the same dir (0600, `O_EXCL`), `fsync`, `os.replace`. No `/tmp` anywhere. `packages-<serial>.json` uses `state.file_token()` for the serial (`:` → `_`).
- **The whole run has a budget** (`OMARCHY_ANDROID_DEV_TOTAL_BUDGET`, 60 s): `cli.main` arms `SIGALRM`, the handler raises `cli.Deadline` (a `BaseException`), `dispatch` answers `error.code timeout`; `track` disarms it. Python runs the handler between bytecodes, so a `proc.wait()` is interrupted but a stuck C call is not: that is what the store's kill timer will be for in 0.2.0.
- **Boolean settings arrive as words too.** `omarchy bar set costafot.android-dev showSystemApps false` without `--json` stores the string `"false"` in shell.json, which is truthy everywhere (seen 2026-09-05: the Apps page kept listing system apps). `cli.coerce_setting` gives every setting the type of its default (`true/1/yes/on`, `false/0/no/off/""`, anything else the default; strings for the paths) and `Store.flag(key, fallback)` does the same in QML; nothing reads a boolean setting any other way.
- **Notifications and the clipboard are optional.** `notify.send` and `notify.copy_file` run `omarchy-notification-send` / `wl-copy` as argv with a 5 s timeout and return False on any failure; the screenshot is already on disk. `notify:false` in the settings silences notifications; nothing else is affected.
- **Nothing is killed by name.** The only children signalled are the ones `Adb.run`, `track`, `record` and the three QML `Process`es hold; no `pkill`, no `pgrep` outside the tests, no PID files. The helper and its adb children carry `PR_SET_PDEATHSIG` (SIGTERM) because the shell ends a `Process` with SIGKILL when its owner is destroyed. The tests' `pgrep` patterns are anchored to the fake adb's own command line (`^/usr/bin/python3 .*fakeadb\.py …`): a shell whose argv mentions the word (a heredoc through the Bash tool) matched `pgrep -af fakeadb.py` on 2026-09-05.
- **The IPC verb for the developer toggles is `flip NAME`, never `toggle`**: that name opens and closes the panel (the kit's convention, and `IpcHandler` has one function per name). The helper's command stays `toggle`.
- **The shell's children inherit an ignored SIGINT.** Quickshell starts its `Process`es with SIGINT in the ignored set, and an ignored disposition survives exec while a handled one resets to default. The helper installs its handlers (`track`, `record`) *before* it spawns adb, `die_with_parent` (every `adb.popen` child's preexec) puts SIGINT back to `SIG_DFL`, and the recorder stops its adb client with SIGTERM anyway. Seen 2026-09-05: `record stop` from the service did nothing because the adb child had inherited `SIG_IGN` (`grep SigIgn /proc/PID/status`, bit 0x2) while the same code worked from a terminal. Nothing may rely on SIGINT reaching a grandchild.
- **Stopping a recording is a hang-up, not a kill.** Ending the adb client closes its socket; adbd sends the remote shell SIGHUP; screenrecord handles SIGHUP and writes the `moov` atom. Verified 2026-09-05 on API 37: the device file stopped growing within 0.5 s and matched a `--time-limit` run byte for byte in shape. The helper waits for two equal non-zero `stat -c %s` reads before pulling; never pull a file that is still growing. There is no `record.json` and no `record stop` in the helper: a terminal recording ends with Ctrl-C, the service's ends with the signal to its own Process (no PID files, invariant below).
- **Detached launches are left alone.** `tools.launch` starts scrcpy, the emulator and the logcat terminal with `start_new_session=True`, stdin/stdout/stderr on `/dev/null` (a child holding the helper's stdout would keep the store's collector waiting for EOF; `test_launched_tools_get_no_pipes_from_the_helper` pins it), SIGINT back at `SIG_DFL`, **no** PDEATHSIG (they must outlive the helper), wrapped in `uwsm-app -- …` when it is on PATH (Omarchy's own launchers do the same; `OMARCHY_ANDROID_DEV_LAUNCHER=""` bypasses it in tests). That wrapper matters: the shell runs inside the `wayland-wm@hyprland.desktop.service` cgroup, and a child spawned from it plainly would die with a restart of that unit; verified 2026-09-05 that an emulator started from the Tools page sits in its own `app-….scope` under `app.slice` (`cat /proc/$(pgrep -f 'qemu-system.*-avd Medium_Phone')/cgroup`). The helper waits `LAUNCH_GRACE` (0.5 s) and reports `no_tool` `X exited at once (code N)` if the tool died, otherwise it never looks again. Nothing launched here is signalled by the plugin; an emulator stops through `adb emu kill`, which it handles itself. `emulator -list-avds` answers in milliseconds here, but the call has a 15 s deadline like everything else. **scrcpy gets `ADB=<the resolved adb>` in its environment** (`launch(argv, name, env=…)`): the `scrcpy` package depends on `android-tools`, whose `/usr/bin/adb` would otherwise be the one scrcpy picks off PATH, and a client of another protocol version kills the running server and takes the tracker's `track-devices` with it. Verified 2026-09-05: `/proc/<scrcpy pid>/environ` carries the SDK path and its adb child is `~/Android/Sdk/platform-tools/adb -s emulator-5554 shell … scrcpy-server.jar …`; `test_scrcpy_is_pointed_at_the_helpers_adb` pins it.
- **`input text` is one line of printable ASCII.** `text.check` refuses anything else (`bad_args`, with the reason); `text.encode` turns spaces into `%s` (input's own escape) and `shlex.quote`s the result, because adbd runs the joined arguments through the device shell before `input` sees them (`test_send_is_one_argv_entry`: `rm -rf / ; echo` arrives as `'rm%s-rf%s/%s;%secho'`). A literal `%s` in the text becomes a space on the device; documented, not worked around. The clipboard is read with `wl-paste --no-newline -t text`: without `-t text` an image on the clipboard came back as PNG bytes (seen 2026-09-05, a screenshot from an earlier test), with it wl-paste refuses (`not available as requested type`) and the helper says `The clipboard does not hold text`.
- **`adb install -r -t`**: `-t` lets a debug build marked `testOnly` install (Windows used `-r` alone). The install is the host verb, so a `Failure [INSTALL_FAILED_…]` lands on stderr with exit 1 and `apk.failure_text` cuts that bracket out for the row. Install all is sequential from the panel, one helper run per file, because one run has one 60 s budget and a 70 MB debug APK needs a few seconds each.
- **A run that hits its budget kills the adb call in flight.** `run_bounded` catches any `BaseException` escaping `proc.wait()` (the alarm's `Deadline`, a Ctrl-C), terminates the child and re-raises; before 0.5.0 an `adb install` interrupted by the alarm went on to finish unseen.
- **No string in the tree names a privilege-escalation, package-manager, service-manager or clone-and-run command** (the seven tokens are in the plan file's invariant 17; the marketplace baseline flags each as a capability and a maintainer then has to rule on it). Say "install the `android-tools` package or the SDK platform-tools" without a command. This sentence is worded the way it is for the same reason.
- Formatting is Python's job (`fmt.py`: labels, `on`/`off`, sizes, paths with `~`, the device `detail` line); QML renders strings and never builds one from device data (the hub appends only literals and counts). Every field is cut at 256 characters with `\r`, ANSI sequences and control characters removed; lists are capped (devices 32, packages 4000, permissions 512, AVDs 64, APKs 200, recent deep links 10).
- The manifest's `version` is the single source of truth (`androiddev.plugin_version()`); bump it with the CHANGELOG in the same commit. The manifest `defaults` must equal `cli.SETTING_DEFAULTS` and the schema must list the same keys in the same order (`test_manifest_defaults_match_the_helper`).
- **Glyph escapes through the tools.** Any `\uXXXX` typed into a tool call arrives as the character itself and a PUA character is then dropped, so the file ends up with `""`. Writing QML through a Python script, spell the escape without typing it: a placeholder such as `@u{f205}` expanded with `chr(92) + "u" + hex`. Check with `grep -c 'icon: ""'` afterwards.
